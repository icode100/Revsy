# Google quiz parser

This CPU service converts question-paper and answer-key PDFs into schema-2
quizzes using the server-side Gemini Flash API. It reuses Firebase Authentication,
Firestore imports, and private Firebase Storage paths. Existing schema-1 MCQ
quizzes and their attempts remain readable.

The container has no Hugging Face token, PaddleOCR model, CUDA, or Torch dependency.
Gemini receives the uploaded PDFs; complete original question pages are rendered
from the supplied PDF and stored for visual review of diagrams and scanned math.
The pages are not generated by the model. The parser
supports MCQ, MSQ, and numeric-answer questions, answer ranges, paper sessions,
sections, one/two-mark questions, and GATE negative marking.

Numeric keys preserve explicit alternative ranges in `additionalRanges`;
disjoint ranges are graded separately. Diagram-based answer options use neutral
letter references to the original page rather than model-inferred descriptions.

## Runtime configuration

| Variable | Purpose |
| --- | --- |
| `GEMINI_API_KEY` | Server secret, supplied by Secret Manager in production. |
| `GEMINI_MODEL` | Defaults to `gemini-3.8-flash`. |
| `FIREBASE_PROJECT_ID` | Existing Firebase/Google Cloud project. |
| `FIREBASE_STORAGE_BUCKET` | Provisioned private Firebase Storage bucket. |
| `FRONTEND_ORIGIN` | Exact HTTPS Hosting origin; exact local HTTP origin for development. |
| `CLOUD_TASKS_QUEUE` | `projects/PROJECT/locations/REGION/queues/revsy-quiz-imports`. |
| `TASKS_SERVICE_ACCOUNT` | Dedicated same-project OIDC task identity email. |
| `TASKS_AUDIENCE` | Exact default Cloud Run HTTPS service origin. |
| `PARSER_PUBLIC_URL` | Same origin, used for `/internal/process` callbacks. |

Cloud Run uses Application Default Credentials from its dedicated runtime
service account. Do not upload a Firebase Admin private key or put the Gemini key
in any `VITE_*` variable, image layer, Docker build argument, or Hosting file.

## Requests and processing

`POST /api/jobs` verifies the browser's Firebase ID token and owned PDF paths,
creates an immutable Firestore import, and schedules a deterministic Cloud Tasks
task. `/api/health` is a lightweight health endpoint. Legacy local `/jobs` and
`/health` paths are also available.

`POST /internal/process` accepts only a verified Google OIDC ID token with the
configured audience, verified email, and configured task-service-account email.
It claims a Firestore lease and processes the import during the HTTP request.
Task metadata headers do not establish identity. Duplicate task delivery is
handled through the durable job state and lease.

This is deliberately request-bound work. Cloud Run can suspend CPU after a
request returns, so a production service must not rely on an overnight poller or
a background thread started after the enqueue response. One Cloud Tasks dispatch
at a time limits model work. Cloud Run concurrency is four so enqueue and health
requests remain responsive while one processing request runs.

Firebase Hosting has a [60-second rewrite timeout](https://firebase.google.com/docs/hosting/cloud-run).
The task callback goes directly to Cloud Run, outside Hosting, with a maximum
30-minute dispatch deadline. Deployment uses a matching 1,800-second Cloud Run
timeout; see [Cloud Tasks HTTP target limits](https://docs.cloud.google.com/tasks/docs/creating-http-target-tasks).

Each worker uses a 1,680-second processing budget, leaving approximately two
minutes before the infrastructure deadline for terminal state writes and
shutdown. Gemini operation timeouts use remaining time, and polling, response
chunks, stage transitions, and source rendering check the budget.

Owned, immutable key/question extraction checkpoints support recovery without
repeating completed phases. Provider inference is not automatically replayed on
quota errors, timeouts, or an unconfirmed response. Interrupted task delivery
can retry its durable lease and reuse saved checkpoints. A response lost before
checkpoint persistence cannot be reused and may require another extraction.
If task creation fails after the import document is saved, the browser's
**Retry starting import** button resubmits that same queued import and uploaded
paths. Production has no background queue reconciler; deterministic owner/import
task IDs make this explicit scheduling retry idempotent.

The supplied full 2021 GATE CS paper/key passed local parsing with 130 questions
(68 MCQ, 26 MSQ, 36 numeric), 200 marks, and 83 preserved original source pages.
This local result does not verify production Cloud Run, billing, IAM, or active
security policies. Their deployment checks are described in the guide below.

## Build

The Docker build context is the repository root. The Dockerfile-specific ignore
file permits only the runtime packages and dependency file into that context:

```powershell
docker build -f services/quiz-gemini/Dockerfile -t revsy-quiz-gemini .
```

For a cloud build, use the deployment planner's frozen allowlisted context rather
than submitting the repository root. The planner never reads `.env` files or
uploaded question papers.

See [the Google deployment guide](../../docs/google-quizzes.md) for the offline
plan, production permissions, local test path, and billing controls.
